# rxhome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sideloadable Android phone app that shows and controls rexserver, the FireStick/Philips TV, Tapo lights and one-tap scenes, greying out whatever it can't reach.

**Architecture:** Device clients are plain Java with no `android.*` imports (`Adb`, `FireTv`, `SwitchBot`, `Tapo`, `Server`, `Scenes`), so they run and are tested on the desktop JVM and against the real devices. Thin Android activities (`MainActivity`, `RemoteActivity`, `SettingsActivity`) call them on a background executor and paint the Stealth UI in code. Settings live in `SharedPreferences`.

**Tech Stack:** Java 8 source, Android SDK 34 command-line tools (aapt2/d8/apksigner), no Gradle, minSdk 26. Android's built-in `org.json`; on the desktop the tests use `~/.gradle/caches/modules-2/files-2.1/org.json/json/20240303/*/json-20240303.jar`.

**Spec:** `docs/superpowers/specs/2026-11-17-rxhome-design.md`

## Global Constraints

- Package `com.andrea.rxhome`; APK `build/rxhome.apk`; `build.sh` modelled on `../rxVision/build.sh` (same SDK/JDK paths, `--min-sdk-version 26 --target-sdk-version 30`).
- Device classes import nothing from `android.*`.
- Every network check has its own timeout of 1500 ms; one dead device never blocks another.
- Grey = unreachable, never shown as "off".
- Secrets (SwitchBot token/secret, Tapo email/password) only in app-private `SharedPreferences`; never logged; never in the repo.
- FireStick keys: `input dpad keyevent <code>`. Sleep 223, wake 224. Never send 26.
- Look: background `#0a0a0a`→`#151517`, tiles `#18181c` with 3px left border `#ff1e3c`, accent `#ff1e3c`, buttons `#232328`, font Chakra Petch (bundled, OFL).
- Defaults: server `http://192.168.1.166:8096`, FireStick `192.168.1.49`.

## Review Focus

1. Phone away from home (mobile data, no WireGuard): every LAN card must go grey within ~1.5 s and SwitchBot buttons must still work. → test in Task 6 (`Server` against a closed port returns UNREACHABLE fast).
2. FireStick ADB key not yet accepted on the TV: first connect must show "Accept the prompt on the TV" instead of hanging. → test in Task 3 (`Adb` AUTH path with an unknown key times out with `AdbAuthException`).
3. Wrong SwitchBot token/secret: show the API's message, not a crash. → test in Task 4 (non-100 `statusCode` throws with the message).
4. Malformed scene text typed on the phone: show the bad line number, keep the old scenes. → test in Task 2.
5. Server power pressed by accident: confirm step required. → manual check in Task 8.

### Task 2: Scenes (parse + seed)

**Interfaces — Produces:**
- `final class Scenes { static List<Scene> parse(String text) throws ParseException; static final String DEFAULT; }`
- `final class Scene { final String name; final List<String[]> steps; }` — each step is its tokens, e.g. `{"light","all","on","20"}`.

Format (my call, replaces the spec's JSON: easier to type on a phone, parses on the JVM): one scene per line, `Name: step; step; …`. Blank lines and `#` comments ignored. Valid steps:
`light <name|all> on|off [0-100] [warm|cool|<kelvin>]` (multi-word light names in quotes), `tv on|off`, `tv app <package>`, `tv music`, `server press`, `wait <seconds>`.

`DEFAULT`:
```
Movie night: light all on 20; tv on; wait 5; tv app org.rxfilms.tv
Music: light all on 60 warm; tv on; wait 5; tv music
Gaming: light all on 30; light "LED strip" on 100
All off: tv off; light all off
```

### Task 3: ADB client

**Files:** Create `src/com/andrea/rxhome/Adb.java`, `test/com/andrea/rxhome/AdbTest.java`

**Interfaces — Produces:**
- `Adb(String host, int port, KeyPair key)`; `String shell(String cmd, int timeoutMs) throws IOException` (opens connection lazily, reuses it, reconnects once on failure); `void close()`.
- `static KeyPair generateKey()` (RSA 2048); `static String publicKeyString(RSAPublicKey k, String name)` (Android adb format, as in `adbkey.pub`); `static KeyPair load(byte[] pkcs8, byte[] x509)`.
- `class AdbAuthException extends IOException` — thrown when the device hasn't accepted our key within the timeout.

Protocol: 24-byte LE header (cmd, arg0, arg1, len, crc=sum of bytes, magic=cmd^0xffffffff), version `0x01000000`, maxdata 4096, `CNXN` payload `host::\0`. On `AUTH` type 1 (token): sign with `Signature.getInstance("NONEwithRSA")` over SHA-1 DigestInfo prefix `3021300906052b0e03021a05000414` + token, reply `AUTH 2`; if answered with another `AUTH`, send `AUTH 3` with `publicKeyString`, then wait for `CNXN` (user accepts on TV). `OPEN` `shell:<cmd>\0` → collect `WRTE` (reply `OKAY` each) until `CLSE`.

Pubkey format: little-endian `int len=64`, `int n0inv = -(n^-1 mod 2^32)`, `n` 256 bytes LE, `rr = (2^2048)^2 mod n` 256 bytes LE, `int e`; base64 + `" " + name`.

- [ ] Step 1: Tests: `publicKeyString` of the key in `~/.android/adbkey` (PKCS#8 PEM) equals the first field of `~/.android/adbkey.pub` (skip if file missing). Live test, only when env `RXHOME_ADB=192.168.1.49` is set: with that key, `shell("getprop ro.product.model")` trims to `AFTMA08C15`. Auth test: fresh `generateKey()` against the live device with timeout 2000 throws `AdbAuthException` (live only; it will pop a prompt on the TV — dismiss it).
- [ ] Step 2: Run → fail. Step 3: implement. Step 4: `RXHOME_ADB=192.168.1.49 ./test.sh` → pass. Commit `adb client`.

### Task 5: Tapo client

**Files:** Create `src/com/andrea/rxhome/Tapo.java`, `test/com/andrea/rxhome/TapoTest.java`

**Interfaces — Produces:**
- `Tapo(String ip, String email, String password)`
- `JSONObject info() throws IOException` (`get_device_info`; fields used: `device_on`, `brightness` (absent on plugs), `color_temp_range` (absent if unsupported), `model`, `nickname`)
- `void set(Boolean on, Integer brightness, Integer kelvin) throws IOException` (nulls omitted; kelvin dropped if `info()` has no `color_temp_range`)
- KLAP helpers, package-private and pure: `static byte[] authHash(String email, String password)` = sha256(sha1(email)+sha1(password)); `static Session klapSession(byte[] local, byte[] remote, byte[] authHash)` with `key = sha256("lsk"+local+remote+auth)[0:16]`, `iv = sha256("iv"+…)` (first 12 bytes = iv base, last 4 = start seq, signed big-endian), `sig = sha256("ldk"+…)[0:28]`; `byte[] encrypt(String)` = sha256(sig+seq+cipher)‖cipher with AES/CBC/PKCS5 over iv base+seq; `String decrypt(byte[])`.
- Handshake: POST `/app/handshake1` (16-byte local seed) → 32 bytes remote seed + server hash (check `sha256(local+remote+auth)`); POST `/app/handshake2` with `sha256(remote+local+auth)`; requests `POST /app/request?seq=N` with `TP_SESSIONID` cookie. On handshake1 404 or non-200: fall back to securePassthrough (RSA 1024 `handshake` → AES key/iv from `key`, `login_device` with base64(sha1hex(email)) / base64(password), `securePassthrough` + `token`).

- [ ] Step 1: Tests: `authHash` and a `klapSession` encrypt for fixed seeds (`local=00..0f`, `remote=10..2f`, email `a@b.c`, password `pw`, payload `{"method":"get_device_info"}`, seq start from iv) equal values computed once with a short `python3` + `cryptography` script written in the test's comment; `decrypt(encrypt(x)) == x`.
- [ ] Step 2–4: fail → implement → pass. Commit `tapo client`. (Live check happens in Task 9 once the user enters credentials.)
