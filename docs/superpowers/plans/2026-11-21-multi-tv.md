# Multi-brand TVs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rxhome controls Samsung, LG and Philips TVs (plus a FireStick on them) in any home, paired once each, picked automatically on the current Wi-Fi.

**Architecture:** A `Screen` interface (the TV's own network API) with `Samsung`, `Lg`, `Philips` implementations; `FireTv` becomes stick-only. A `Tv` composite holds an optional `Screen` + optional `FireTv` and routes each command (spec "Routing" + "Remote switch"). Saved TVs live as one JSON list in prefs (`Tvs`); Discovery finds TVs by SSDP and matches them to saved ones by id.

**Tech Stack:** Plain Android SDK, Java, no Gradle, no new dependencies. `org.json` (already used). Tests: `./test.sh` (desktop JVM, `java -ea`, one `main` per `*Test.java`, asserts).

**Spec:** `docs/superpowers/specs/2026-11-21-multi-tv-design.md`

## Global Constraints

- No new dependencies; no `android.*` imports in any class that has logic worth testing (test.sh compiles only files without `import android.`).
- Self-signed TLS (Samsung 8002, LG 3001, Philips 1926): pin the certificate's SHA-256 (lowercase hex) at pairing; accept only that cert after.
- Keys stay Android keycodes end to end (`Gestures.UP=19, DOWN=20, LEFT=21, RIGHT=22, OK=23, HOME=3, BACK=4, PLAY_PAUSE=85`, MENU=82, REWIND=89, FF=90, VOL_UP=24, VOL_DOWN=25, MUTE=164, TV_INPUT=178, SLEEP=223, WAKEUP=224); each `Screen` maps them to its own names.
- A command the active TV can't do: hidden/greyed in UI, `UnsupportedOperationException` from the API, skipped-and-reported in scenes. Never a silent no-op.
- The scan never pairs or prompts: only a user tap in *Add a TV* starts a pairing (TV prompt or ADB key offer).
- Existing user setup (`firetv`, `philips_*` prefs) migrates to saved TV #1 with no re-pairing.
- Remote switch default: FireStick. Remembered per saved TV.
- Copy: "No TV on this Wi-Fi", "Add a TV"; LG add screen must say to enable *Turn on via Wi-Fi* (a.k.a. *Mobile TV On*) for power-on.

## Review Focus

1. **Two homes, same IPs** (both TVs at 192.168.1.221): the app must match by id, never act on the wrong home's TV. → test in Task 6 (`matchByIdNotIp`).
2. **Saved TV switched off / unplugged**: scan finds nothing; card shows "No TV on this Wi-Fi"-style away state, not a crash or endless spinner; power-on still tries Wake-on-LAN with the saved MAC. → test in Task 7 (`powerOnWhenScreenUnreachable`).
3. **Pairing refused or timed out on the TV** (user taps Deny / ignores prompt): pairing call throws an `IOException` with a readable message; nothing saved. → tests in Tasks 2 and 3 (`pairDenied`).
4. **TV's cert changed** (factory reset, other TV at same IP): connection refused, message says to pair again; never falls back to trusting. → test in Task 1 (`wrongPinRefused`).
5. **Old saved prefs with a Philips but no id yet**: first scan adopts the id by brand+IP once, then matches by id. → test in Task 6 (`migratedPhilipsAdoptsId`).

Apps: emit `ed.installedApp.get` / `ed.apps.launch` (`action_type` `DEEP_LINK`). `isOn`: `device.PowerState` of api/v2 (`"on"` → true, `"standby"` → false, missing + answers → true, no answer → null). `powerOff` = `KEY_POWER` only when `isOn()` is true. `setVolume` unsupported (`can("volume")` false); `mute` = `KEY_MUTE` (a toggle; note in code).
